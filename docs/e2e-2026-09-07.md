## Incidents on the way (all fixed in the branch)
1. `InstalledPlugins/` is wiped by the extension manager on restart → deploy to the manual `Plugins/` folder.
2. `fork` inside the LMS process (the scan runs in-process on macOS; STDOUT/STDERR are tied to the log trapper) turned each child into a live server clone → 40+ LMS copies, load > 500, machine down twice. Fixed with perl's list-form pipe open.
3. `sacd://` URLs were treated as remote by LMS and never stored in the library → `file://…iso#2ch-NN` anchor URLs with a URL-regexp protocol handler, like cue sheets.
4. Player status polls on a volatile entry re-read the ISO tags every 30 s → `getTag` now returns only the container when the children already exist.
5. Unrelated but relevant on this box: `coreduetd` runaway after the crashes (reset with `launchctl kickstart -k system/com.apple.coreduetd`); the LMS menu-bar wrapper does not restart the server, and `open -a` does not either once the server has been killed.
