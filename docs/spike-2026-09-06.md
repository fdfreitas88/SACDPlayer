Conclusions:
- This disc has no DST/multichannel track, so no real DST decode timing was captured. The 2ch DSD-uncompressed track 1 (5:55) extracted in 2.575 s real time (~138× realtime) — extremely fast because the source is local disk, not SMB, and DSD tracks here are stored uncompressed (no DST decode cost).
- Because no DST timing is available from this disc, `extract_timeout_s` cannot be derived from measured DST decode time. As a conservative placeholder pending a real multichannel/DST-disc measurement, use `extract_timeout_s = 600` (10 min) — well above any observed or expected single-track extraction time on this hardware, and consistent with the brief's "3× slowest track time" heuristic applied to a worst-case few-minute DST decode. This value should be revisited once a genuine multichannel SACD ISO is available for measurement.
- "Preparando" wait for a DST track of 5 min: no DST data available from this disc; using the same conservative assumption, budget up to ~60–120 s of "Preparando" wait before assuming a stall, to be re-measured against a real DST disc.

## Update 22:35 — real DST measurement over SMB (Birds Of Fire, Audio Fidelity 2015, 2ch + 5ch areas)

ISO on `//192.168.0.30/Disk8TB` (SMB), binary from the installed plugin, i5-2435M.

| Measure | Result |
|---|---|
| 5ch (DST) track 1, 5:50 | **6 min 56 s** wall, 685 s user (170 % CPU) → **1.19 × realtime, i.e. slower than the track** |
| 2ch (plain DSD) track 1, 5:50 over SMB | 20.5 s wall, 21 % CPU → 17 × realtime, I/O-bound |
| Output sizes | 5ch DSF 612 MB, 2ch DSF 247 MB |

Conclusions: stereo areas extract fast enough for the lazy first play (about 3.5 s per minute of music over SMB).
Multichannel DST areas cannot be extracted faster than realtime on this CPU: the first play of an mch
track waits longer than the track itself, and the 600 s default `extract_timeout_s` would kill any mch
track longer than ~8 min. Default raised to 1800 s; mch albums should be prepared manually ahead of time.
